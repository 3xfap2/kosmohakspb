# Протоколы проверок

Как воспроизвести: `npm install`, затем `npm test` (115 проверок) и `npm run results`
(пересчёт сохранённых расчётов в `results/`). Вероятностные тесты используют фиксированный seed,
поэтому повторный запуск даёт те же числа.

## 8. Монте-Карло

**Распределения:** отказ канала в год — испытание Бернулли с вероятностью, равной единице минус
надёжность канала из `reliability_profile`. Тяжесть события — снижение фактической поставки на 30%.
**Зависимости:** отказы считаются независимыми. Это допущение команды, а не установленный факт.
**Параметры:** 1 000 прогонов, seed 42, генератор mulberry32.
**Воспроизводимость:** проверена тестом — два запуска с одним seed дают идентичный результат, с разным
seed результат отличается.

## 15. Дедлайн решения и эффект инвестиций

**Вход.** Лучший план стандартного сценария, условия обязательного стресса.

**Что проверяем.** `decisionDeadline` прогоняет анализ адаптации по каждому году горизонта и
возвращает, чем и до какого момента дефицит ещё закрывается.

| Проверка | Ожидаемое | Фактическое |
|---|---|---|
| Годы разбора | весь горизонт 2035–2040 | совпадает с `getBaseYears()` |
| Монотонность | чем позже узнали, тем больше остаток дефицита | 0 → 0 → 0 → 0 → 51,3 → 120,3 т |
| Последний год реакции | максимум из закрывающих лет | 2038 |
| Штатные каналы | Earth-Flex и Earth-Core не закрывают дефицит | ни в один год горизонта |
| Спокойный сценарий | закрывать нечего | дефицит базы 0,0 т |

**Результат.** Штатными каналами дефицит стресса не закрывается ни при какой дате обнаружения:
Earth-Flex ограничен свободной мощностью, Earth-Core — сроком поставки. Аварийный канал закрывает
дефицит полностью за 2 537 млн у.е., но только если решение принято не позже 2038 года.

**Эффект инвестиционных решений.** Сравнение с нижней границей «Без инвестиций» в стандартном
сценарии: приведённые расходы 9 353 → 8 715, полные 11 635 → 10 578, тонна обслуженного спроса
8,38 → 7,61 млн у.е. при CAPEX 1 430 млн.

**Воспроизведение.** `npm test` (блок «Дедлайн решения»), `npm run results` →
`results/decision_deadline.csv`, `results/investment_effect.csv`, раздел «Дедлайн решения» в `results/summary.md`.

## 16. Независимая проверка и закрытие замечаний

Комплект проверялся отдельно от разработки: проверяющий читал постановку, критерии и стартовый
репозиторий организатора, ничего не меняя в проекте. Ниже — содержательные находки и что сделано.

### Область действия ограничений сценария

**Было.** Производные сценарии (чувствительность, обратный стресс, реестр рисков, Монте-Карло,
геополитика) получают идентификатор вида `BASE+SENSisru0.5`. Ограничения сравнивались с ним строкой,
поэтому требования сервиса 97%/99%, заданные для `BASE`, переставали быть жёсткими во всех
производных расчётах и не попадали в список нарушений.

**Стало.** Сравнение идёт по базовому сценарию (`scenario_id.split('+')[0]`).
Тест «требования сервиса остаются жёсткими в производном сценарии» в `engine.test.ts` фиксирует это:
при падении поставки лунного канала вдвое проверки сервиса имеют роль `hard` и дают нарушение.

**Следствие для выводов.** Граница прочности пересчитана: падение поставки ISRU ломает план
при −5%, а не при −10%, как было записано ранее. Расхождение усиливалось грубой сеткой обратного
стресс-теста (шаг 10%); шаг уменьшен до 5%.

### Срок поставки лунного канала

**Было.** Канал считался доступным с января 2038 года на полную мощность, хотя срок поставки после
ввода — 1–2 месяца.

**Стало.** В первый рабочий год доступно 10 месяцев из 12. Заказ 2038 года снизился со 120 до 100 т.
Тесты: «в первый рабочий год доступна не вся мощность» и «со второго года канал доступен полностью».

### Физика хранилища

**Было.** Переполнение фиксировалось проверкой `STORAGE_OVERFLOW`, но объём сверх ёмкости оставался
в балансе и обслуживал спрос следующих месяцев.

**Стало.** Запас ограничен активной ёмкостью, излишек выводится из баланса отдельной величиной.
Тесты: «запас никогда не превышает активную ёмкость» и «месячный баланс сходится с учётом излишка».

### Начальный запас подготовительного периода

**Было.** Закупка начального запаса оплачивалась только по цене тонны: без платы за резервирование
мощности и без потерь на поступлении.

**Стало.** Поставка рассчитывается с учётом потерь, резервирование мощности начисляется по тем же
правилам, что и для обычного заказа. Тест «оплачивается с резервированием мощности и несёт потери».

### Надёжность первого рабочего года нового поставщика

**Было.** Пониженная надёжность 0,88 применялась к 2035 году, в котором канал ещё не работает.

**Стало.** Первый рабочий год определяется доступностью канала в конкретном плане.

### Реестр рисков

**Было.** Четыре риска из пяти сгенерированы циклом с дословно одинаковыми причиной, владельцем и
мерой; аварийный канал исключён из реестра, хотя назван мерой для остальных; зависимостей нет.

**Стало.** Причина, владелец, мера и основание тяжести различаются по природе канала; аварийный канал
включён в реестр; добавлен риск срыва срока ввода лунного производства; в выгрузке появились колонки
`severity_basis` и `dependencies`. Тесты проверяют, что причины и владельцы не повторяются.

### Представление неисполнимых вариантов

**Было.** Вариант «добрать объёмы через Emergency» подавался как способ закрыть дефицит, хотя сам
нарушает 45-дневный резерв в 2038–2040 годах; колонки причины в выгрузках адаптации, дедлайна и
чувствительности не было.

**Стало.** Во всех трёх выгрузках и на экране есть причина нарушения; дедлайн различает «закрыл
выдачу» и «остался исполнимым». Формулировки в записке, демо-сценарии и шпаргалке переписаны.

### Карта соответствия критериям

**Было.** Статус «выполнено» проставлен литералом по всем 21 пункту, а подпись утверждала, что он
считается по расчёту.

**Стало.** Поле статуса убрано: оценку выставляет жюри, карта отвечает только на вопрос «где смотреть
и чем подтверждено».

### Многокритериальный выбор

**Было.** Сравнение шло по первым 16 стратегиям из 36, отобранным по расходам, и в пул не попадал
вариант «Без инвестиций» — именно тот, который важен профилю с максимальным весом CAPEX.

### Что осталось незакрытым

- Презентация и передача репозитория на GitVerse выполняются вне этого комплекта.
- Take-or-pay считается верно, но не участвует в ранжировании стратегий: каналы сравниваются по цене
  тонны и ставке резервирования. Это оговорено в шпаргалке отдельным вопросом.
- Монте-Карло по-прежнему предполагает независимые отказы каналов; совместные отказы моделируются
  только сценариями реестра рисков и геополитического блока.
